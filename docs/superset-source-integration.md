# Report Builder integration into the Superset fork

[Source-verified scope] Compared Report Builder `b0a610a` with Apache Superset 6.1.0 at `c83fb2bb1dcfac41ac51bcebd82471f4a7180d18`. The paths proposed below are additions to the fork. A review of fork-specific changes and a live run in Superset remain pending. [Upstream revision](https://github.com/apache/superset/commit/c83fb2bb1dcfac41ac51bcebd82471f4a7180d18)

[Recommendation] Mount the existing editor as a Superset page. Give it a protected builder API for catalog, preview, saved definitions, and publication. The product boundary is a published Superset dataset that opens in native Explore.

## 1. Page, navigation and authentication

**[Verified in the pilot]** `ReportWorkspace` already takes a catalog, report client, library client, and schedule store. `ReportBuilder` takes a client and a saved definition. The standalone entry point owns `ReactDOM.render`, the launcher token, CSS imports, and the top-level shell. The API transport uses root-relative `/api/`, and `make_app` uses a loopback-only cookie. Use the existing `@expose`, `@has_access`, `@permission_name("read")`, and `render_app_template()` pattern. In `SupersetAppInitializer.init_views()`, register the view/menu and `ReportBuilderRestApi` via AppBuilder. Add a lazy route in `superset-frontend/src/views/routes.tsx` for a new `src/pages/ReportBuilder/index.tsx`. The existing `App.tsx` supplies user bootstrap data, navigation and the application root. The first page can mount `ReportBuilder` with its Superset client. Scope the pilot's `:root`, `body`, `table`, and `dialog` styles to the page and bundle its icon through the host. Connect `ReportWorkspace` as its library and scheduling adapters become available. Use Superset's configured `SupersetClient` for the host session and CSRF. ## 2. Catalog, filter values and preview

**[Verified in the pilot]** `model.py` fixes Sales, Customer and Product identities and two many-to-one relationships. The CSV executor joins dimensions used by either selected fields or active filters. It filters before summing and sorts independently of column position. The browser limits `Entity` to the three pilot entities and `Definition.source` to `sales`. It also hardcodes entity order and the default field for **Add filter**. Filter values come from an entire individual dimension or fact collection. Use `class_permission_name = "ReportBuilder"` with a dedicated `@permission_name("publish")` alongside read and edit. Derive the database, source dataset, join path and physical fields from an approved server-side catalog keyed by stable field IDs. Pass entity order and the initial filter field through that catalog. Generalize the browser’s entity and source types when adding a second source. Keep existing Sales field IDs and definition versions readable. Superset's reflection already exposes foreign keys. Business labels, approved edges and a join's allowed cardinality are builder configuration. Use one validated field, filter, and sort plan for preview and publication. For detail previews, omit `metrics` and `groupby` so Superset preserves duplicate detail rows. ## 3. Save and publish

**[Verified in the pilot]** `ReportStore.save()` validates the definition and checks revisions under a process-local lock. It persists a UUID, title, definition and revision to JSON. The browser contract has preview, save and open methods. Publish needs its own operation and a link to the native dataset. [Report storage](../report_store.py#L190-L232) · [Client contract](../ui/src/client.ts#L13-L23)

**[Proposed in the fork]** Add a builder report model and Alembic migration in Superset's metadata database. Store the owner, report UUID, definition, draft revision, catalog revision, and the published dataset ID and revision. Record the published SQL checksum and field-to-alias mapping so a direct dataset edit or incompatible change can be detected. Add `POST /api/v1/report_builder/reports/{id}/publish` with the expected saved revision. Return the native dataset ID, the published revision, and the output aliases. The endpoint checks the report owner, publish permission and the current user's access to the configured source before using the native dataset commands. Plain Gamma receives HTTP 403 from the stock dataset-create API in the release test. Use a named Report Builder Author role with the required builder, source and Explore/Chart permissions. The SQL source check can use access to the registered physical dataset. Grant that source specifically so authors can publish within the approved scope. [Native dataset API](https://github.com/apache/superset/blob/c83fb2bb1dcfac41ac51bcebd82471f4a7180d18/superset/datasets/api.py#L100-L108) · [Gamma create test](https://github.com/apache/superset/blob/c83fb2bb1dcfac41ac51bcebd82471f4a7180d18/tests/integration_tests/datasets/api_tests.py#L776-L790) · [SQL source permission check](https://github.com/apache/superset/blob/c83fb2bb1dcfac41ac51bcebd82471f4a7180d18/superset/security/manager.py#L2524-L2561)

1. Compile the validated definition to a single read-only PostgreSQL SELECT from that plan, with stable aliases and typed filters. Resolve identifiers from the approved catalog and let the database dialect quote parsed values when compiling the saved SQL. Keep the 50-row preview limit at query time. A summary dataset groups at the selected grain.
2. Use `CreateDatasetCommand` for first publication. It checks access to SQL sources and calls `fetch_metadata()`. Use `UpdateDatasetCommand` followed by metadata refresh for a compatible edit. Refresh reconciles columns by name. The native `override_columns` path can replace existing column records, so use refresh with preserved aliases and validate the result. [Create](https://github.com/apache/superset/blob/c83fb2bb1dcfac41ac51bcebd82471f4a7180d18/superset/commands/dataset/create.py#L42-L105) · [Update](https://github.com/apache/superset/blob/c83fb2bb1dcfac41ac51bcebd82471f4a7180d18/superset/commands/dataset/update.py#L66-L119) · [Refresh](https://github.com/apache/superset/blob/c83fb2bb1dcfac41ac51bcebd82471f4a7180d18/superset/commands/dataset/refresh.py#L40-L77) · [Column merge](https://github.com/apache/superset/blob/c83fb2bb1dcfac41ac51bcebd82471f4a7180d18/superset/connectors/sqla/models.py#L1773-L1854) · [Column replacement](https://github.com/apache/superset/blob/c83fb2bb1dcfac41ac51bcebd82471f4a7180d18/superset/daos/dataset.py#L262-L322)
3. Wrap native metadata operations and the builder's publication link in a single outer `@transaction`. The decorator defers commit for nested commands using `g.in_transaction`. Lock the report row and compare the expected revision to make retry at that revision return the existing dataset. Verify rollback on failed refresh on the fork. [Transaction implementation](https://github.com/apache/superset/blob/c83fb2bb1dcfac41ac51bcebd82471f4a7180d18/superset/utils/decorators.py#L235-L275)

**[Assessment]** Treat a change in summary grouping, metric definition or output type as a compatibility change. A new grouping field may split one row into several, even when every existing alias survives. For the first in-place republish test, add a detail column while preserving fact grain, or prove that the summary addition preserves its grain. Offer **Publish as new** for changes that alter an existing chart's meaning. Superset already returns dependent charts and dashboards through the dataset's `related_objects` endpoint. [Dependency lookup](https://github.com/apache/superset/blob/c83fb2bb1dcfac41ac51bcebd82471f4a7180d18/superset/datasets/api.py#L792-L837)

## 4. Open in Explore and qualify data access

**[Verified in Superset]** `SaveDatasetModal` passes the real dataset ID to `postFormData()` and opens `mountExploreUrl('base', …)` with the returned form-data key. The API checks datasource access and stores temporary Explore state. Reuse those helpers in the fork page after publication commits. Retry the Explore handoff from the existing published dataset if Explore state creation fails. Use `query_mode: 'raw'` for the Table chart over an already-grouped SQL dataset. Supply `all_columns` in display order and encode `order_by_cols` as ordered `[alias, ascending]` pairs. The Table chart feeds those into the chart query. - **[Source-verified sort difference]** The pilot puts nulls last in either direction. The native query renderer uses plain ascending or descending expressions, and PostgreSQL descending defaults to nulls first. Preserve and test priority separately from output order. Give the builder's paged results a stable final tie-breaker when selected sort keys tie. Prove the first handoff with non-null sort keys and qualify null-last parity separately. [Pilot sorting](../csv_source.py#L167-L174) · [Superset ordering](https://github.com/apache/superset/blob/c83fb2bb1dcfac41ac51bcebd82471f4a7180d18/superset/models/helpers.py#L3277-L3296) · [PostgreSQL sort rules](https://www.postgresql.org/docs/17/queries-order.html) · [PostgreSQL paging rules](https://www.postgresql.org/docs/17/sql-select.html#SQL-LIMIT)
- **[Source-verified access difference]** SQL Lab uses a separate RLS flag, which defaults to false. The virtual dataset path attempts to apply source policies and logs failures before continuing. Use PostgreSQL-enforced source scope for the first proof. Before sharing the same published dataset across restricted audiences, prove that row policies are enforced before aggregation and that policy failures stop the query. Check both fresh and cached results. Builder-only field visibility does not restrict native Explore. Expose reviewed projections for the first audience and use dataset-specific grants for restricted users. Test access through both the builder and direct native chart requests.
